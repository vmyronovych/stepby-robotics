# Прошивка Мандрівника v0.3

**Цільова компіляція успішна:** ESP32 Dev Module / ESP-WROOM-32 (DevKit V1 30-pin), Arduino-ESP32 **3.3.0**, flash **4 МБ**, два OTA розділи по **1 966 080 байтів**. У прошивці вже є український Blockly-редактор, інтерактивний 3D-гайд, виконавець програм, керування моторами/лінією та браузерне OTA. Фізичні випробування на платі ще не проведені.

[Браузерне середовище](../web/README.md) · [API та байткод](../docs/workshop-protocol.md) · [електрика](../docs/wiring.md) · [результати](../validation/report.md).

## Перше встановлення — вчитель, USB

1. S1 вимкнути, **AA зняти та J5 (+5 В/GND) фізично від’єднати**. Не живити одночасно від USB і регулятора.
2. В Arduino IDE додати індекс `https://espressif.github.io/arduino-esp32/package_esp32_index.json`, установити **esp32 by Espressif Systems 3.3.0**.
3. Вибрати **ESP32 Dev Module**, flash **4MB**, **Partition Scheme → Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)**. Не C3/S3, не WROVER. `src/partitions.csv` задає саме цю схему; зберігати його поруч зі скетчем.
4. Відкрити `src/src.ino`. `main.cpp` та всі `.h` у цій папці є частинами скетчу. Готовий `workshop_assets.h` містить редактор; npm для такого USB-запису не потрібен.
5. Підключити USB data до самого ESP32 (USB плати розширення тільки для живлення), вибрати порт, Verify → Upload. Якщо треба, утримати BOOT на початку завантаження. Після запису відкрити Serial Monitor **115200**, натиснути EN і записати `Teacher PIN: XXXXXX` та SSID. PIN унікально створюється на платі, у публічному `.bin` його немає.
6. Від’єднати USB, повернути J5 і заряджені NiMH; підняти колеса, увімкнути S1. Робот не повинен рушати. Wi-Fi `Mandrivnyk-XXXXXX`, початковий пароль `Mandrivnyk32` (змінюється в `config.h`).
7. Відкрити **http://192.168.4.1**. Перевірити датчики, полярність кожного мотора через **http://192.168.4.1/control**, калібрування і весь приймальний протокол. Після цього — урок.

Альтернатива для підготовленого робочого місця з Arduino CLI:

```sh
arduino-cli core update-index --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core install esp32:esp32@3.3.0 --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
sh tools/build_firmware.sh
arduino-cli board list
arduino-cli upload --fqbn esp32:esp32:esp32:PartitionScheme=min_spiffs --port /dev/PORT --input-dir firmware/build firmware/src
```

Замінити `/dev/PORT` реальним портом. Сценарії не прошивають підключений пристрій автоматично. `MCAR_ARDUINO_CLI` може задати шлях до CLI; локальна конфігурація `.cache/arduino-cli.yaml`, якщо є, використовується лише в цьому робочому середовищі.

## Справжні Wi-Fi оновлення `.bin`

У новій майстерні: **Для вчителя → Оновлення прошивки**.

1. Зарядити AA, забезпечити стабільне живлення. Поріг входу в режим — VBAT_SW ≥4,6 В після D0. Поставити робот на стійку підставку з вільними колесами.
2. Ввести шестизначний PIN із Serial. Натиснути «Увійти в режим оновлення»: мотори блокуються.
3. Утримуючи фізичну кнопку робота, натиснути «Підтвердити кнопкою робота». Відпустити кнопку.
4. Упродовж 60 с обрати **`mandrivnyk-esp32-ota.bin`** із поточної збірки/папки `release` і надіслати. Дочекатися завершення та перезапуску. Не від’єднувати живлення.
5. Приєднатися до Wi-Fi знову за потреби, перезавантажити сторінку. Налаштування/MCAR2 у NVS зберігаються, автоматичного руху немає.

OTA-файл — лише application image, **не** `.merged.bin`, bootloader або partitions. Розмір, тип ESP32-образу та цілісність перевіряються. Образи іншого виробу для класичного ESP32 можуть технічно пройти системну перевірку, тому використовувати лише збірки цього проєкту. Криптографічної перевірки видавця немає. Завантаження неперевіреної, хоча й валідної прошивки може вимагати USB-відновлення; автоматичного rollback на цій конфігурації немає.

USB recovery-файл `mandrivnyk-esp32-usb.bin` у `release` — об’єднаний образ 4 МБ для запису з offset **0x0** через esptool. Він **стирає/замінює також дані NVS**, включно з калібруванням, програмою і PIN; призначений для першого встановлення/відновлення, не OTA. Для звичайного першого запису рекомендовано шлях Arduino IDE вище.

## Збірка після змін

Редактор потребує Node/npm, прошивка — Arduino CLI і core 3.3.0:

```sh
npm ci --prefix web
npm run build --prefix web
sh tools/build_firmware.sh
```

`web/scripts/embed.mjs` формує gzip-масиви HTML/JS/CSS/SVG/ліцензії; усі ресурси входять у app image. Тому один OTA оновлює і C++, і редактор, без окремої файлової системи. Команда створює `firmware/build/mandrivnyk-esp32-ota.bin`. Не використовувати схему Huge APP / No OTA.

## Рух і захист

Карта GPIO незмінна: моторні пари 16/17, 18/19, 23/25, 26/27; сенсори 32/33/34/35/36; батарея 39; FAULT 21/22; кнопка 13. Класичний ESP32 має 8 потрібних LEDC каналів. 20 кГц, 8 біт; PWM програмно обмежений 180/255. Апаратні шунти драйверів обов’язкові.

- Пуск після boot/reset лише явною командою; утримана фізична кнопка забороняє новий запуск. Фізична кнопка під час руху зупиняє; її відпускання не повинно запускати інший режим. Новий мережевий режим скасовує попередній дозвіл запуску від кнопки.
- Коротке натискання у спокої запускає лінію; довге ≥1 с — збережену програму. Програма/лінія автономні й обмежені 120 с. Втрата Wi-Fi їх не зупиняє; S1 та фізична кнопка доступні завжди.
- Ручний режим `/control`: heartbeat 100 мс, тайм-аут 350 мс; epoch відкидає запізнілі команди після STOP.
- FAULT або VBAT_SW<4,2 В 500 мс зупиняють і блокують рух до перезапуску після усунення причини.
- Розгін до 6 PWM/20 мс; реверс через нуль і ≥100 мс вільного обертання. STOP негайно задає нуль PWM, але колеса фізично можуть докочуватися.
- Калібрування: біле, потім широке чорне, по 32 вибірки; кожен канал має контраст ≥300 ADC. Зберігається у NVS.
- P-керування: ваги −2,−1,0,+1,+2; left=speed+Kp×error, right=speed−Kp×error, межі 0…180. speed=0 дає нуль незалежно від помилки. Утрата лінії — негайний нуль і STOP через 100 мс; усі п’ять темні — STOP як перехрестя.
- Під час OTA всі режими руху заблоковані. Після невдалого оновлення або виходу робот не стартує сам.

## Сумісність із попереднім набором

`/control` зберігає старі кнопки напрямку, послідовності «Мої блоки», налаштування speed/Kp, моторні тести. Старі `/program` і `/run` та текстові приклади `lessons/programs` працюють. Основна адреса `/` тепер відкриває повноцінний Blockly-редактор; там інший формат MCAR2 і файли `.mcar`. У старих уроках «Зберегти в роботі» для нового редактора відповідає «Надіслати роботу», а цикл квадрата вже можна скласти одним блоком повторення.
