# USB-майстерня Мандрівника

Єдиний редактор проєкту: українські блоки Blockly, власні команди з параметрами, конструктор підключень і запис програми на ESP32 через USB. Почати можна без плати кнопкою «Продовжити без плати».

## Локальний запуск

```sh
npm ci --prefix web
npm run dev --prefix web
```

Відкрийте **http://127.0.0.1:5173/** у Chrome або Edge. Для запису приєднайте ESP32, надайте доступ до USB-порту й натисніть «Прошити програму». Перше налаштування плати виконується за підказками застосунку. [Інструкція для класу](../docs/classroom-web-usb.md).

«Роздивитися машинку» відкриває 3D-гайд поверх редактора. «До блоків», Escape та завершення останнього кроку повертають до тієї самої програми без перезавантаження чи повторного вибору USB. Пряме посилання — `/#assembly`, доступне без підключення плати. [Складання](../docs/assembly-guide.md).

Старі адреси `/usb.html` та `/robot.html` перенаправляються до головної зі збереженням query-параметрів і `#assembly`. Wi-Fi-редактор, його опитування робота, OTA-панель, готові блоки руху та окремий компілятор прибрані з вебзастосунку. Дані USB-проєктів зберігаються під тим самим ключем; старе локальне сховище Wi-Fi-проєктів не стирається і не конвертується автоматично.

## Збірка та перевірка

Якщо під час локального прошивання з’явилося `Failed to fetch dynamically imported module` для `browser-flasher.js` або HTTP 504 для `/node_modules/.vite/deps/`, не тримайте BOOT: модуль прошивача ще не завантажився, запис не почався. Збережіть проєкт, зупиніть dev-сервер (Ctrl+C), виконайте з кореня репозиторію `npm run dev --prefix web -- --force` і оновіть вкладку. Це відновлює кеш залежностей; повторне натискання «Прошити» у старій вкладці може повторювати закешовану помилку імпорту. Не видаляйте кеш і не перевстановлюйте залежності при працюючому dev-сервері. Перевірка реального dev-імпорту без запису на плату: `npm run test:e2e --prefix web -- dev-flasher.spec.js`.

```sh
npm test --prefix web
npm run build:site --prefix web
cd web
npx vite preview --host 127.0.0.1
```

`npm run build` і `npm run build:site` створюють той самий статичний застосунок у `web/dist`. Публікуйте цю папку через HTTPS (наприклад, GitHub Pages). Відносні адреси підтримують вкладений шлях `/mcar/`. Збірка більше не перезаписує `firmware/src/workshop_assets.h` старого Wi-Fi-виконавця; історичні firmware/release-матеріали відокремлені від поточної вебмайстерні.

Браузерні перевірки (з `web/`):

```sh
npx playwright test
node scripts/check-production.mjs
```

Для `check-production.mjs` потрібен запущений preview на порту 4173. У тестах прошивання використовується імітація USB; фізична перевірка плати — окремий крок.

Додатковий локальний Arduino-сервіс для розробника доступний через `/?transport=local`; клас використовує звичайний браузерний USB-режим. [Локальний сервіс](../docs/usb-workshop.md).
