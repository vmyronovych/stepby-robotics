# Прокладання проводів у конструкторі

## Керування

Клік по піну відкриває довідку без зміни схеми. Перетягни від піна до піна для нового проводу; можливе місце підключення підсвічується під курсором. Альтернатива — «Під’єднати провід» у довідці та вибір кінцевого контакту. Esc або кнопка «Скасувати підключення» скасовує дію. Для перенесення наявного проводу спочатку вибери його й тягни кінцеву ручку.

Натисни провід. Квадратні ручки зсувають горизонтальний або вертикальний відрізок, круглі — збережені згини. Подвійний клік по проводу додає згин. Перетягування прив’язане до сітки; Alt дозволяє вільне розташування. Сфокусовані ручки підтримують стрілки клавіатури; Delete або Backspace на круглій ручці видаляє згин.

«Автоматичний маршрут» у властивостях проводу прибирає його ручні точки. Іконка розведення у верхній панелі робить це для всіх проводів. Обидві дії підтримують Undo/Redo. Після ✓ ручні точки зберігаються у проєкті разом із блоками. Геометрія проводу не змінює контакти, електричну перевірку або призначення GPIO.

## Дослідження та вибір

Використано [libavoid](https://www.adaptagrams.org/documentation/libavoid.html), бібліотеку ортогонального прокладання з обходом перешкод, яку використовує Inkscape. Інтеграція — [libavoid-js](https://github.com/Aksem/libavoid-js), зафіксована версія 0.4.5, WebAssembly. Рушій рахує схему разом, враховує довжину, згини, перетини та спільні коридори. Готовий алгоритм доповнений керуванням ручними маршрутами у нашому SVG-редакторі.

Порівнювалися також:

- [JointJS Manhattan router](https://docs.jointjs.com/api/routers/): придатний для сітки та обходу компонентів; перехід на модель JointJS тут зайвий.
- [JointJS libavoid standalone](https://docs.jointjs.com/learn/features/automatic-layouts/standalone-link-routing/): підтверджує використання libavoid окремо від розміщення вузлів. Наші фізичні піни й breadboard потребують власного адаптера.
- [React Flow editable edges](https://reactflow.dev/examples/edges/editable-edge): корисний приклад взаємодії з ручками; приклад належить Pro, а редактор не використовує React Flow. Код прикладу не копіювався.

## Адаптація до електроніки

Корпуси плат і деталей — перешкоди. Breadboard є поверхнею для монтажу: проводу дозволено проходити над нею до потрібного отвору. Для вставленого LED та резистора перешкодою є корпус, а не вся прямокутна область зображення з ніжками. Контакти залишаються фіксованими; згладжуються лише кути між ними.

Bindings 0.4.5 не відкривають нативний `setRoutingCheckpoints`. Тому збережені ручні точки задають ланцюжок конекторів libavoid. Ці точки не створюють електричних вузлів. Якщо переміщений компонент перекрив ручну точку, вона тимчасово пропускається; її координати залишаються у проєкті, а властивості проводу показують пояснення.

Рушій працює у Web Worker. Виконується один розрахунок і зберігається лише останнє очікуване завдання; результат застосовується тільки до відповідного стану схеми. Дедлайн розрахунку — 2,5 с. За відмови WASM або перевищення дедлайну працює запасне JS-прокладання. Відкриття конструктора заново повторює завантаження рушія. Для понад 24 проводів або 48 ручних точок дорогі оптимізації перетинів вимикаються.

Запасний режим не гарантує обходу всіх перешкод, якщо вільний маршрут неможливий. Перетин намальованих проводів сам по собі не означає електричного з’єднання. Це редактор схеми, не фізична симуляція кабелів.

## Розповсюдження

WASM завантажується з того самого сайту, без CDN, і збирається з відносними URL для GitHub Pages. LGPL-текст та архіви відповідних вихідних кодів libavoid-js/adaptagrams включені в `public/third-party/libavoid/`. WASM залишається окремим замінюваним файлом; бібліотеку не модифіковано.
