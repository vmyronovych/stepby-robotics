# Блоки → USB → ESP32 у комп’ютерному класі

Мета: на Windows 10/11 учень відкриває HTTPS-сайт у настільному Chrome або Edge, підключає ESP32, складає блоки і натискає «Прошити». Node.js, Python, Arduino IDE та локальний сервер учням не потрібні. Браузер показує власне вікно вибору порту; сайт не обходить цей дозвіл. Windows-приймання на шкільних ПК ще необхідне перед production-релізом.

## Сценарій учня

1. Відкрий сайт. Початковий екран пропонує підключити micro-USB або натиснути **«Продовжити без плати»**. Без плати доступні блоки, «Мої блоки», розпіновка, конструктор підключень, перегляд коду та збереження/відкриття проєктів. Вибір запам’ятовується в цій вкладці після оновлення сторінки. Редактор доступний і без підтримки Web Serial; у такому браузері кнопка підключення вимкнена з поясненням. Коли будеш готовий, натисни **«Підключити ESP32»**: це відкриє звичайне підключення та перевірку, не записуючи програму. Після готовності плати натисни «Прошити програму».
2. Підключи ESP32 кабелем із передаванням даних. Першого разу натисни «Кабель підключено — обрати ESP32» та вибери USB Serial / Silicon Labs CP210x у вікні браузера. Сайт не може побачити нову плату до надання дозволу. Уже дозволена плата знаходиться автоматично через події `connect` / `disconnect` та перевірку доступних портів.
3. Майстерня перевіряє готовність плати командою HELLO; це не записує й не запускає новий алгоритм. Якщо сумісний приймач відповів, автоматично відкривається редактор. Якщо не відповів, показано «Відновімо зв’язок» з повторною перевіркою та діагностикою. Встановлення базової прошивки обирається окремо; відсутність відповіді не означає, що прошивки немає.
4. Перше налаштування встановлює базову прошивку й приклад блимання. Уже збережені блоки не змінюються; незавершений алгоритм не заважає підготувати плату.
5. Склади алгоритм і натисни «Прошити». Під час передавання видно лише стан запису; після завершення повертається редактор. Наступні оновлення обходяться без BOOT.
6. Якщо кабель від’єднати, повертається екран підключення; звідти можна продовжити без плати. Якщо цей режим уже обрано, редактор залишається доступним. Блоки зберігаються. Після повернення дозволеної плати перевірка та перехід до редактора автоматичні, без запису програми.
7. Програма виконується на ESP32 автономно. Після перезапуску EN або нового живлення вона починається знову, навіть із закритим сайтом.

Кожен комп’ютер працює зі своєю платою. Програми не надсилаються на сервер. Проєкти зберігаються в цьому браузері; для іншого ПК використай «Зберегти» / «Відкрити» (.mcar). Кілька вкладок не можуть одночасно відкрити один USB-порт.

## Програмування через розпіновку

Натисни картку **ESP32** праворуч. Відкриється інтерактивна 3D-модель саме 38-контактної плати з фото: можна обертати її, показати зворотний бік або повернутися до вигляду спереду. Натискання на контакт чи його підпис відкриває доступні дії. Без WebGL залишається 2D-карта.

- **Увімкнути / вимкнути** — цифровий вихід 1 / 0.
- **Змінити яскравість** — PWM, ціле число 0–255, частота 5 кГц. На GPIO2 потрібен підключений світлодіод; вбудований LED є на цьому піні не у всіх варіантів плати.
- **Прочитати сигнал** — умова з цифровим входом без внутрішнього підтягування.
- **Перевірити кнопку** — умова з внутрішнім підтягуванням; кнопка між обраним GPIO та GND, натискання відповідає рівню 0.
- **Прочитати датчик** — аналогове значення 0–4095 записується у змінну `датчик GPIO…`. Це сире 12-бітне значення, не виміряна напруга.

«Додати до програми» вставляє блок після вибраного блока; без вибору — в кінець програми або тіла останнього нескінченного циклу. Читання сигналу / кнопки додає готову умову зі світлодіодом усередині. Для постійного опитування помісти її у «завжди». Додавання скасовується одним Undo. При виборі блока картка показує його GPIO, а розпіновка підсвічує відповідний контакт. Файл .mcar і локальне автозбереження зберігають усі нові блоки.

Дії запускаються **після прошивання**. Графічна плата не показує поточний електричний стан контактів. GPIO34/35/36/39 дозволені лише для читання й не мають внутрішнього підтягування; SP = GPIO36, SN = GPIO39. Контакти пам’яті, живлення, EN та UART0 не програмуються. Для GPIO0/2/5/12/15 показано зауваження про запуск плати. Карта можливостей звірена з [документацією GPIO Espressif](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/gpio.html); PWM використовує [LEDC Arduino-ESP32](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html). Поточний виконавець не вмикає Wi-Fi, тому ADC2 доступний. Сигнали мають бути в межах 0–3,3 В; двигун потребує драйвера.

Виконавець окремо перевіряє дозволені GPIO і дії навіть для зміненого байткоду; нечислове / неціле PWM або значення поза 0–255 зупиняє програму. При помилці налаштовані виходи переходять у 0, PWM від’єднується. Після нормального завершення останні задані рівні / PWM зберігаються до перезапуску або нової команди. Цифрова команда на тому самому піні від’єднує його від PWM.

## Одноразова підготовка вчителя

- Актуальний настільний Chrome або Edge, доступ до HTTPS-сайту й дозвіл на serial-пристрої в політиках школи.
- ESP32 / ESP-WROOM-32 із щонайменше 4 МБ flash, як перевірена плата власника. ESP32-C3/S3 та інші сімейства поки відхиляються до запису.
- Для плати з CP2102 Windows має бачити COM-порт. Якщо драйвер відсутній, його встановлює адміністратор із [сайту Silicon Labs](https://www.silabs.com/software-and-tools/usb-to-uart-bridge-vcp-drivers). Сайт не встановлює системні драйвери.
- Перевірити кабель, відсутність зайнятого COM-порту та автоперезапуск. На деяких платах при підключенні завантажувача треба утримувати BOOT; інтерфейс підказує це.
- Блоки підтримують GPIO2 LED, цифровий вихід, PWM, цифровий / аналоговий вхід і кнопку з підтягуванням. Контакти пам’яті та UART0 зарезервовані. Зовнішні датчики й навантаження підключають із учителем; мотор потребує драйвера.

Web Serial потребує дозволу користувача та захищеного контексту. Chrome документує [роботу Serial API](https://developer.chrome.com/docs/capabilities/serial); адміністратор Edge може керувати дозволами через [SerialAskForUrls](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/serialaskforurls).

## Як працює запис без сервера

Blockly компілюється **у браузері** в обмежені інструкції MCARUSB1. На ESP32 постійно працює базова прошивка з виконавцем і USB-приймачем алгоритмів. Після її встановлення «Прошити» передає тільки алгоритм: без переходу в ROM-завантажувач, без BOOT і без повторного завантаження файлів прошивки із сайту. Алгоритм зберігається у flash і працює після EN / нового живлення без браузера.

Якщо сумісна базова прошивка відповіла на USB-запит, використовується швидке передавання. Якщо відповіді немає, відкривається відновлення зв’язку без завантаження пакета й ROM-запису. Відпусти BOOT, перепідключи USB та натисни «Перевірити підключення». Розділ «Діагностика USB» показує час, етап, ідентифікатор USB та останню відповідь; пароль Wi-Fi і PIN приховано. Якщо плата відповіла зі старою версією середовища, майстерня окремо пропонує оновлення.

Після сну або повернення до вкладки майстерня закриває попередню USB-сесію й перевіряє плату знову, без запису. Перевірка відкладається до завершення поточного передавання. Для завислих відкриття, запису та закриття USB встановлено таймаути; після такого таймауту потрібно перепідключити USB й оновити сторінку, щоб не використовувати незавершену сесію повторно.

Перше встановлення доступне окремою дією в розділі «Перше налаштування або свідоме перевстановлення», повторне — також у налаштуваннях підключення. Воно замінює програму на платі тестом блимання. **Лише для встановлення базової прошивки може знадобитися BOOT.** Якщо ROM-завантажувач не під’єднався, майстерня повертає екран відновлення з причиною збою, без автоматичного повтору встановлення. Помилка вже розпізнаного приймача також не запускає повне перепрошивання.

Під час звичайного оновлення дані спочатку збираються в RAM. Перевіряються довжина, CRC32, усі інструкції, переходи, стек і дозволені GPIO. Лише повний коректний алгоритм записується у неактивне місце flash. У розділі 64 КБ є два місця по 32 КБ; підтвердження запису з номером версії записується останнім. Попередня програма залишається доступною при обриві передавання або живлення під час запису нового алгоритму. Після підтвердження збереження виходи попередньої програми вимикаються і запускається нова. Відключення після успішного збереження, але до відповіді браузеру, може залишити новий алгоритм уже записаним — у такому випадку інтерфейс не стверджує, що запис не відбувся.

Кожний сеанс має власний ідентифікатор; плата підтверджує кожен пакет, CRC збереженої програми та її запуск. Браузер спостерігає перші 750 мс виконання для негайних помилок. Це не доводить правильність довільного майбутнього циклу. Під час першого встановлення додатково перевіряються SHA-256 файлів, модель ESP32, щонайменше 4 МБ flash, MD5 записаних образів і маркер запуску протягом 7 секунд.

Розділи: bootloader 0x1000, partition table 0x8000, factory application 0x10000 (3 МБ), program 0x310000 (64 КБ). Перше встановлення очищає обидва місця з алгоритмами й записує поточні блоки. Пакет не сумісний із попередньою OTA-схемою робота; це окремий режим для навчання на GPIO та світлодіоді.

Поточний пакет: `web/public/firmware/esp32-gpio-v2/`; відтворення для розробника — `sh tools/build_browser_firmware.sh` із налаштованим Arduino-ESP32 3.3.0. Manifest фіксує хеші джерел і бінарних файлів; тести відхиляють застарілий пакет після зміни runtime. [Протокол і схема збереження](../firmware/browser/README.md).

## Статична збірка та GitHub Pages

```sh
npm ci --prefix web
npm test --prefix web
npm run build:site --prefix web
cd web
npm run test:e2e -- --config playwright.browser-usb.config.js
npm exec vite -- preview --host 127.0.0.1 --port 4173
```

`http://127.0.0.1:4173/` відкриває готовий сайт без API компіляції/запису. Публікується тільки `web/dist`. Його головна сторінка — USB-редактор; `#assembly` — 3D-гайд у тій самій USB-майстерні. «До блоків» закриває гайд без перезавантаження редактора. Старі `/usb.html` і `/robot.html#assembly` перенаправляються на головну сторінку зі збереженням параметрів адреси. Відносні шляхи перевіряються тестом у `/mcar/`, тому працюють у project Pages і на окремому домені.

Workflow `.github/workflows/pages.yml` запускає тести та збірку. Репозиторій платформи — [vmyronovych/stepby-robotics](https://github.com/vmyronovych/stepby-robotics). Один раз обери Settings → Pages → Build and deployment → Source → GitHub Actions. Кожний push у `main`, зокрема після злиття PR, автоматично публікує `web/dist`, якщо всі перевірки успішні. PR лише перевіряються; deploy дозволений виключно з `main`. Для повторного запуску обери Actions → Classroom website → Run workflow, гілку `main` та `deploy_pages=true` (увімкнено за замовчуванням). Вимкни цей прапорець для ручної перевірки без публікації. Запуски однієї гілки не переривають поточний deployment. Сайт після успішної публікації: https://vmyronovych.github.io/stepby-robotics/.

Локальна стара C++-компіляція збережена для розробника: `http://127.0.0.1:5173/usb.html?transport=local`. Учням цей режим не потрібен.

## Приймання на Windows перед класом

На одному Windows 10 і одному Windows 11 під обліковим записом учня: перше підключення, дозвіл браузера, блимання 0,2/1 с, повторний запис, закриття сайту й перезапуск EN, від’єднання/повторне підключення, скасування вибору порту та зайнятий COM-порт. Повторити в установлених Chrome/Edge, потім одночасно на кількох учнівських ПК. До виконання цих перевірок це кандидат для пілотного запуску, не підтверджений classroom production-реліз.

### Світлодіод і індикатор USB

Блок «світлодіод GPIO2» керує тим самим виходом, що й «пін GPIO2». Наявність програмованого вбудованого LED не визначається за назвою ESP32 чи USB-ідентифікатором CP210x. На деяких платах видимий індикатор лише коротко спалахує під час обміну через USB. Успішне передавання алгоритму підтверджує запис і запуск, а не фізичне світіння LED. Перед заняттям перевірте, який світлодіод встановлено на конкретних платах.


## Мої блоки

Категорії палітри працюють як акордеон: натисни назву, щоб розкрити блоки безпосередньо під нею. Повторний клік згортає категорію, а вибір іншої закриває попередню. Палітра залишається в лівій колонці й прокручується незалежно від полотна; перетягування справжніх блоків у програму збережено.

### Вибір кількох складових і копіювання

В основному редакторі та у вікні власної команди утримуй **Shift** і клацай блоки або обведи їх рамкою, починаючи з вільного фону. Кнопка **«Вибрати»** вмикає цей режим без клавіатури. Сині контури й лічильник показують вибір; повторний клік у режимі вибору прибирає блок із нього.

Компактна панель у правому верхньому куті полотна розкриває дії після вибору блоків. Вона та меню правої кнопки мають копіювання, вирізання, дублювання та видалення вибраного. **Ctrl/⌘+C, X, V, D** виконують відповідні дії, **Delete/Backspace** видаляє, **Ctrl/⌘+A** вибирає всі доступні блоки. **Ctrl/⌘+Z** скасовує всю групову дію; **Ctrl/⌘+Shift+Z** або **Ctrl/⌘+Y** повертає її. Esc скидає груповий вибір/режим. Усередині текстових полів ці клавіші працюють із текстом.

Копіюються лише вибрані команди: сусідні невибрані команди ланцюжка не додаються. Вкладений вміст циклу чи умови копіюється разом із вибраним контейнером. Після вирізання решта ланцюжка з’єднується назад. Можна копіювати складові між основним полотном і редактором власної команди в межах відкритої сторінки. Буфер не зберігається після оновлення сторінки. Для перенесення виклику нової команди спочатку збережи її визначення.

### Незалежна копія власної команди

У відкритій команді натисни **«Дублювати команду»**, або наведи на блок у категорії «Мої блоки» й натисни іконку дублювання. Також є пункт **«Створити копію цієї команди»** у меню її виклику. Копія має нове визначення та назву з додатком «— копія»: зміни назву, GPIO чи інші складові та збережи. Редагування копії не змінює оригінал. Звичайне копіювання блоку-виклику на полотні створює ще один виклик того самого визначення. Вкладені виклики інших власних команд і спільні змінні зберігають свої посилання.

### Створення команди

Готові блоки руху прибрано з палітри та стартових прикладів. Учень складає власні команди з GPIO, пауз, умов і повторень у USB-майстерні.

1. Натисни **«＋ Мій блок»** або відкрий категорію **«Мої блоки» → «Створити блок»**.
2. Назви команду та з’єднай її складові під **«виконати»**. Натисни **«Зберегти блок»**.
3. Перетягни нову команду з категорії **«Мої блоки»** у програму. Її можна використовувати багато разів і всередині інших власних команд.
4. Подвійний клік на команді відкриває її складові. У палітрі іконки редагування й дублювання з’являються при наведенні на команду або фокусі клавіатури. На сенсорному екрані вони видимі постійно. **«Назад»** повертає до зовнішньої команди; остаточне **«Зберегти блок»** зберігає всі вкладені зміни.
5. Щоб об’єднати вже складену послідовність, відкрий контекстне меню першої команди й обери **«Згорнути цю й наступні команди в мій блок»**. Вибрана команда та весь наступний ланцюжок заміняться одним викликом.

Зміна визначення впливає на всі його використання. «Скасувати» або Escape закриває редактор без збереження чернетки. Збереження та згортання можна скасувати стандартною дією Undo. Визначення, яке ще використовується, не можна видалити — спершу прибери його виклики.

Файл `.mcar` та локальне збереження містять усі визначення. Команди підтримують параметри, але не повертають результат: до 32 визначень, до 8 рівнів вкладення, без прямого чи непрямого самовиклику. Змінні спільні для програми та власних блоків; параметри локальні для виклику. Обмеження розміру виконуваної програми зберігаються; велика кількість викликів може перевищити їх.

### Параметри: одна команда для різних моторів

У редакторі команди розкрий **«Параметри» → «Додати параметр»**. Для кожного задай назву, тип і початкове значення:

- **Число** — швидкість, пауза, кількість повторів. Перетягни рожевий параметр із категорії «Параметри» на місце числа; його можна включати у вирази.
- **Умова** — наприклад, «Вперед». Перетягни параметр в умову «якщо», щоб вибирати між двома послідовностями команд.
- **GPIO** — контакт, який обираєш у виклику. Усередині команди в меню GPIO обери **«Параметр: назва»**. Для передачі піна іншій власній команді перетягни рожевий параметр у її GPIO-вхід.

Наприклад, створи команду **«Мотор»** з параметрами **IN3 (GPIO), IN4 (GPIO), Швидкість (число), Вперед (умова)**. Склади потрібні GPIO-команди й дві гілки напряму всередині. Потім перетягни два виклики «Мотор» і задай їм різні піни та швидкості. Алгоритм визначаєш один раз, а значення — окремо для кожного виклику. Наявну команду можна відкрити та поступово замінити фіксовані значення параметрами.

Початкові значення застосовуються до нових викликів і нових параметрів старих викликів. Зміна початкового значення не перезаписує вже задані аргументи. Перейменування зберігає всі посилання та значення. Щоб видалити параметр або змінити його тип, спочатку прибери його використання зі складових і виклики команди. Дублювання визначення переносить його параметри в незалежну копію; скасування редагування не змінює проєкт.

До 6 параметрів у команді. Числа й умови обчислюються один раз на початку кожного виклику. Вкладені виклики мають власні значення. Разом із користувацькими змінними одночасно вкладені числові/логічні параметри використовують до 8 комірок виконавця; послідовні виклики повторно використовують комірки. GPIO обирається до запуску й перевіряється для кожної дії: GPIO34/35/36/39 не стануть виходами через параметр. Параметри не можна переносити в іншу команду звичайним копіюванням складових — користуйся дублюванням визначення.

Власні команди розгортаються у звичайні інструкції під час компіляції. Базову USB-прошивку оновлювати не потрібно. GPIO-команди працюють у USB-виконавці; окремий старий Wi-Fi-виконавець машинки не отримує підтримки GPIO від цієї зміни. Старий Wi-Fi-редактор видалено з вебзастосунку; його проєкти не конвертуються автоматично в USB-формат.

## Графічні підключення

Кнопка **«⌁ Підключення»** у верхній панелі відкриває окреме полотно. Палітра ліворуч містить ESP32 на 38 контактів, чорний DRV8833 HW-627, жовтий мотор-редуктор, батареї 4 × AA NiMH (номінал 4,8 В) і USB комп’ютера. Перетягни модуль на полотно або натисни його в палітрі. Компонент можна назвати та переміщувати, тримаючи за саму плату. Клік по контакту лише відкриває довідку. Щоб додати провід, перетягни його від одного контакту до іншого або натисни «Під’єднати провід» у довідці та обери кінцевий контакт. Esc скасовує підключення. Підписи з’являються при наведенні, фокусі чи виборі контакту; повний список також доступний у властивостях. Вибраний провід можна перефарбувати, перепідключити або видалити. Нові проводи отримують колір автоматично. Фіксована палітра доступна лише у властивостях вибраного проводу.

На полотні модулі показані без карток і винесених убік списків пінів. Зображення та точки підключення використовують одну систему координат 3D-моделі. **«Роздивитися в 3D»** відкриває обертання, передній і зворотний боки. Це змодельовані за фото компоненти, а не метрологічно точні CAD-копії.

Керування наближене до блокового редактора: тягни вільний фон для переміщення полотна, утримуй Space для перетягування поверх компонентів, використовуй Ctrl/⌘ + коліщатко для масштабу під курсором. Праворуч унизу є центр схеми, +/− та кошик. Delete/Backspace видаляє вибране; Ctrl/⌘+Z скасовує, Ctrl/⌘+Shift+Z або Ctrl/⌘+Y повторює зміну. Компонент також можна перетягнути в кошик.

Щоб встановити плату розширення, вибери ESP32 та у властивостях зміни **«Плата розширення» → «ESP32S 38P · S / V / G»**. ESP32 відобразиться вставленою у роз’єми, а доступними стануть фізичні контакти рядів S/V/G. Це одна збірка, яка переміщується разом. Вибір «Без плати розширення» не дозволить втратити наявні проводи: спочатку їх треба від’єднати. Старі схеми з однією окремою платою розширення й ESP32 об’єднуються в чернетці при відкритті зі збереженням кінців проводів; зміна зберігається після «Застосувати».

### Від проводу до команди

1. З’єднай, наприклад, GPIO16 ESP32 із IN1 драйвера, GPIO17 — з IN2, OUT1/OUT2 — з двома проводами мотора. Для живлення драйвера познач VCC від батарей та спільну землю батарей, драйвера й ESP32. USB позначає кабель до самої ESP32.
2. Вибери IN1 та натисни **«＋ Команда ШІМ»** або візьми команду з категорії **«Підключені піни»**. Значення ШІМ — 0…255. Окремою командою керуй IN2. Такі команди можна об’єднати у **«Мої блоки»**; готовий алгоритм руху редактор не нав’язує.
3. Іменована команда зберігає посилання на контакт драйвера. Якщо перенести IN1 на GPIO23, перед застосуванням з’явиться перелік зачеплених команд. Після **«Застосувати»** обидва компілятори використають GPIO23, зокрема всередині власних блоків. Звичайний блок «пін GPIO16» залишається прив’язаним до GPIO16.
4. Контекстне меню команди відкриває її підключення. Дія **«Знайти команди в програмі»** на схемі знаходить використання або відкриває відповідний власний блок. Видалений провід робить залежну команду некоректною й дає пояснення перед записом.

Схема, назви, кольори та результати ручного звіряння зберігаються разом із блоками у `.mcar` та локально в браузері. До застосування редактор працює з чернеткою; «Скасувати» її відкидає. Перепідключення скидає позначки звіряння. Базову прошивку для цієї функції оновлювати не потрібно.

### Межі перевірки

Редактор аналізує електричні мережі намальованої схеми: знаходить замикання живлення на землю, об’єднання джерел, конфлікти GPIO, використання входу як виходу, службові піни, неправильні виходи/пари моторного драйвера та батарейне живлення на 5V одночасно з USB. Виявлені помилки блокують компіляцію. Незавершені підключення й непідтверджені характеристики показуються окремо; відсутність знайдених помилок не означає, що реальний монтаж перевірено.

Напругу батарей, струм і навантаження мотора, перемичку J1/SLEEP та обмеження струму конкретного HW-627 треба звірити вручну. Редактор не вимірює фізичні проводи через USB і не симулює мотор. **«Звір із реальною збіркою»** послідовно підсвічує проводи для ручної перевірки.

Для моделі ESP32S 38P відповідність S/G визначена її розпіновкою та працює одразу після вибору плати. Додаткова галочка не потрібна. Старе поле signalsVerified у збережених проєктах приймається для сумісності та не впливає на доступність GPIO. Напруга V залежить від перемички JUMP; її налаштування залишається окремим.

Розміщення контактів HW-627 відповідає моделі та фото користувача в проєкті. Загальна функція двох H-мостів і керуючих входів звірена з [документацією Texas Instruments DRV8833](https://www.ti.com/lit/ds/symlink/drv8833.pdf); характеристики мікросхеми не гарантують характеристики конкретного модуля.

Уточнення плати розширення за фото: з кожного боку по **17 колонок**, у кожній — S/V/G. Нижній ряд S завершується контактом **5V**. Жовтий S розташований із зовнішнього краю, чорний G — ближче до ESP32. 5V у колонці S є контактом живлення, не програмованим GPIO; він відрізняється від сусіднього ряду V з напругою, залежною від перемички. Внутрішню силову розводку та напругу VCC редактор не визначає за відповідністю сигналів GPIO.

При намальованому зовнішньому живленні на 5V редактор не просить додатково підключати USB: показує потребу звірити напругу/шлях живлення та наявність GND. Одночасний USB і зовнішній плюс на 5V блокуються, оскільки розв’язка конкретної плати не підтверджена. Для оригінальної DevKitC виробник визначає USB та 5V/GND як взаємовиключні варіанти живлення: [Espressif — Power Supply Options](https://documentation.espressif.com/esp-dev-kits/en/latest/esp32/esp32-devkitc/user_guide.html#power-supply-options). Це не є схемою саме цієї сторонньої плати розширення. 4,8 В батарей — номінал, не підтверджена стабілізована напруга 5 В.

### Більше місця для схеми

Усі інструменти, коротка підказка та дії збереження розміщені в компактному хедері; нижньої панелі немає. Кнопки показані іконками з підказками при наведенні та доступними назвами. **✓** застосовує підключення, **×** закриває редактор без застосування чернетки. Іконка палітри згортає та повертає список компонентів.

Права панель з’являється при виборі компонента, контакту чи проводу; клік на вільне полотно або хрестик у панелі знімає вибір і повертає місце полотну. Іконка перевірки відкриває список перевірок і проводів; лічильник показує кількість помилок або незавершених з’єднань. Ручне звіряння також відкриває цю панель. Якщо зміна проводів впливає на команди, у хедері з’являється окрема іконка з кількістю змін: натисни її, щоб переглянути GPIO до застосування. Escape спочатку закриває цей список.

Згортання панелей не змінює проводи й поточний масштаб. На телефоні можна сховати обидві панелі та працювати на всю ширину екрана; підказка займає короткий другий рядок хедера.

### Поворот компонентів

Клавіатура: **R — 90° праворуч**, **Shift+R — 90° ліворуч** для вибраного компонента, його контакту або перемички. В українській розкладці це та сама фізична клавіша **К**. Під час введення тексту поворот не виконується; утримання клавіші не запускає серію поворотів. Ctrl/Cmd+R залишається командою браузера.

Обери компонент або його контакт: у хедері з’являться дві кругові стрілки — поворот на **90° ліворуч** і **90° праворуч**. Обертаються зображення та контакти, а назва залишається горизонтальною. Підключені проводи перебудовуються автоматично, їхні GPIO не змінюються. ESP32 із платою розширення обертаються як одна збірка. Поворот підтримує Undo/Redo і зберігається в проєкті після **✓ Застосувати**; старі проєкти відкриваються з початковою орієнтацією.

### Окрема гребінка GND / VCC / сигналів

За фото власника додано чорну гребінку 2×4 ліворуч від круглого роз’єму живлення. Якщо роз’єми живлення праворуч, верхній ряд зліва направо — **TX, RX, VCC, GND**, нижній — **D22, D21, VCC, GND**. Два GND доступні для проводів; додаткові GND також є в довгих чорних рядах G, і їхні підказки прямо містять GND. D21/D22 відповідають GPIO21/GPIO22 після підтвердження відповідності контактів плати розширення. TX/RX залишені службовими контактами USB-обміну. Фото не підтверджує напругу VCC або його внутрішнє з’єднання з V, 3V3 чи 5V, тому редактор не припускає такого зв’язку.

### Перемичка JUMP і підказка про живлення

Модель показує три вертикальні контакти з підписами **3.3V / V / 5V** та відкритий жовтий корпус перемички на середньому й нижньому контактах, як на фото власника. Це зображення положення **V–5V з фото**, а не визначення поточного положення на підключеній платі.

Картка «Живлення червоних рядів V» пояснює, де знайти JUMP, як звірити її положення та між якими контактами вчителю виміряти напругу перед підключенням модуля. Для VCC окремої гребінки пояснення з’являється лише за наявності намальованого проводу до VCC: положення JUMP не використовується як доказ напруги VCC.

### Інтерактивна перемичка

Натисни жовту **JUMP** на платі: бокова панель покаже малюнок металевого містка, пояснення S/V/G і кнопки **3,3 В / 5 В**. Кнопки переставляють перемичку на моделі та змінюють показану в поясненні напругу червоних рядів. Те саме пояснення доступне у властивостях компонента й через картку перевірки живлення V.

Положення підтримує Undo/Redo, поворот компонента та зберігається разом зі схемою після ✓ Застосувати. Закриття без застосування відкидає зміну. Для старих проєктів початкове зображення відповідає 5 В з фото; це явно позначено. Вибір на схемі не переставляє фізичну перемичку й не підтверджує виміряну напругу, допустимий струм або живлення VCC. Перевірка живлення залишається ручною. На фізичній платі переставляй місток лише після вимкнення живлення.

### Перший урок: зовнішній світлодіод, резистор і mini breadboard

У палітрі **«Світло»** є світлодіод і резистор. У властивостях світлодіода обери червоний, жовтий або зелений колір. A — анод (довша ніжка), K — катод (коротша ніжка біля плаского краю). Колір зображення позначає вибраний компонент, а не результат симуляції чи вимірювання USB.

Опір резистора обирається зі стандартних номіналів E24 від 10 Ом до 1 МОм; початковий — 330 Ом. Корпус одразу показує чотири смуги: дві цифри, множник і золотий допуск ±5%. Наприклад, 220 Ом — червона/червона/коричнева/золота; 330 Ом — помаранчева/помаранчева/коричнева/золота. У властивостях назви кольорів продубльовані текстом. Джерело маркування: [Vishay — Resistor Color Code](https://www.vishay.com/docs/49411/resistor_color_code_calculator.pdf).

У палітрі **«Монтаж»** є білий **Mini breadboard 170** за [посиланням власника](https://prom.ua/p374330930-maketnaya-plata-170.html) і наданим фото (`assembly/references/breadboard-mini/front.png`). Це 17 колонок і 10 рядів отворів. Усередині A–E одного номера з’єднані між собою; F–J того самого номера утворюють іншу групу. Між сусідніми номерами й через центральну канавку з’єднання немає; окремих шин живлення теж немає. Вибір отвору підсвічує його п’ятірку. Джерело принципу роботи: [Adafruit — Breadboards for Beginners](https://learn.adafruit.com/breadboards-for-beginners?view=all).

Резистор і LED вставляються **без проводів**: перетягни компонент так, щоб дві ніжки опинилися біля отворів. Дві зелені позначки показують місце встановлення; відпусти компонент, і ніжки точно стануть в отвори. R повертає на 90° праворуч, Shift+R — ліворуч. Зайнятий ніжкою або проводом отвір не прийме іншу ніжку.

Приклад кола з трьома проводами:

- Поверни резистор вертикально та встав його ніжки в **E5 і F5**, через канавку.
- Встав LED: **A → J5**, **K → J6**.
- Намалюй проводи **GPIO16 → A5**, **F6 → GND ESP32**, **USB комп’ютера → USB ESP32**.

Щоб додати провід до групи зі вставленою ніжкою, обери інший вільний отвір цієї п’ятірки. Наприклад, для K у J6 використай F6–I6. Під час прокладання проводу вставлені деталі стають напівпрозорими, щоб можна було вибрати отвори під ними. Escape скасовує провід і повертає перетягування деталей за корпус.

Встановлені деталі переміщуються й повертаються разом із breadboard. Щоб витягнути деталь, перетягни її за корпус за межі плати або натисни «Витягнути з breadboard» у властивостях. Там також видно номери обох отворів. Видалення макетної плати залишає деталі на полотні, але роз’єднує їх. Undo/Redo і файл проєкту зберігають вставлення. Обидві ніжки LED в одній внутрішній групі викликають зрозумілу помилку.

Після такого з’єднання обери світлодіод і натисни **«＋ Команда увімкнути / вимкнути»** або **«＋ Команда ШІМ»**. GPIO визначається з проводів, вставлених ніжок і внутрішніх груп breadboard. Команди доступні також у категорії **«Підключені піни»** та всередині «Моїх блоків». Для блимання склади цикл: увімкнути → пауза → вимкнути → пауза.

Перевірка цього уроку підтримує прямий активний рівень: GPIO → послідовний резистор → A, K → GND. Резистор може бути й між K та GND, або послідовних резисторів може бути декілька. Без резистора, з обходом резистора, переплутаними ніжками або GPIO лише для входу показується помилка. Нерозпізнані розгалужені резистивні мережі не отримують готову команду GPIO; це перевірка простого навчального кола, не електричний симулятор. Малий опір потребує звіряння струму за характеристиками фактичного LED; колір сам по собі не визначає його точну напругу чи допустимий струм. Параметри, проводи, поворот і групи breadboard зберігаються разом із блоками; діє Undo/Redo.

### Акуратні проводи

Натисни провід: квадратні ручки дозволяють зсувати відрізки, круглі — пересувати згини. Подвійний клік додає згин; Delete на круглій ручці видаляє його. Сітка вирівнює рух, Alt вимикає прив’язку, стрілки клавіатури пересувають вибрану ручку. «Автоматичний маршрут» у властивостях скидає ручні точки одного проводу, іконка розведення в хедері — усіх. Зміни підтримують Undo/Redo та зберігаються після ✓. [Деталі й вибір рушія](wiring-routing.md).

### DRV8833 у mini breadboard

DRV8833 HW-627 теж вставляється без проводів: поверни його на 90° клавішею R і розмісти поперек центральної канавки. Крок сусідніх ніжок відповідає кроку отворів, а відстань між двома рядами — **7 кроків**, за уточненням власника. Приклад: SLEEP → B10, IN4 → F10; решта ніжок займають B9…B5 і F9…F5. Відпусти модуль, коли підсвітяться **всі 12 отворів**. Зайняті або відсутні отвори не дозволяють вставлення.

Контакти з’єднуються з внутрішніми групами breadboard. Наприклад, до IN1 у F5 можна підвести GPIO через вільний J5. Модуль переноситься й повертається разом із макетною платою; у властивостях є «Витягнути з breadboard». Збереження, Undo/Redo й відновлення проєкту зберігають усі 12 місць вставлення. Поворот самого вставленого модуля залишає його вставленим лише за збігу всіх ніжок із вільними отворами, інакше витягає його.

### Якщо «Підключені піни» не дають команд

Категорія показує придатні команди та окремо пояснює підключення, які потребують виправлення. «Показати …» відкриває конкретний контакт і його причину недоступності.

GPIO34, GPIO35, SVP (GPIO36) і SVN (GPIO39) на цій ESP32 — лише входи. Для керування IN драйвера обери вихідні GPIO, наприклад 16 і 17. Для мотора на OUT1/OUT2 потрібні IN1/IN2, для OUT3/OUT4 — IN3/IN4. Факт наявності проводу не робить вхідний GPIO придатним для вихідної команди. Непридатні підключення пояснюються у палітрі, але не використовуються компілятором як виходи.

### Документація контактів плати розширення

У «Підключеннях» натисни фізичний контакт плати ESP32S 38P: угорі бокової панелі відкриється його документація. Для жовтих контактів S показані відповідний GPIO ESP32, призначення, доступні режими та обмеження. Описи й режими беруться з тієї самої моделі пінів, що й розпіновка ESP32; GPIO34/35/36/39 залишаються лише входами. «Показати контакт на ESP32» підсвічує контакт самого контролера.

Червоні V, чорні G та окрема гребінка 2×4 мають власні пояснення. Ім’я стовпчика GPIO не робить V або G програмованим контактом. З документації V кнопка веде до перемички JUMP. Для VCC окремої гребінки напруга залишається непідтвердженою. Відповідність S/G визначає вибрана модель плати; перегляд документації не змінює схему. Клік на пін також починає провід; Esc скасовує його прокладання, залишаючи пояснення відкритим.

### Як знайти незавершені з’єднання

Кнопка перевірки у верхньому правому куті відкриває конкретні помилки й незавершені з’єднання одразу під лічильником. Клік на повідомлення підсвічує потрібний контакт; для вставленого компонента зазначено також отвір breadboard (наприклад, IN1 · C6).

Щоб використовувати плату розширення, вибери ESP32 → «Плата розширення» → «ESP32S 38P · S / V / G». Її сигнали та земля враховуються автоматично. Зберегти схему — верхня кнопка ✓ «Застосувати підключення».

### Перенесення кінця проводу

Щоб перенести провід з OUT2 на OUT4, спочатку вибери потрібний провід на полотні або у списку. На обох кінцях з’являться круглі ручки: потягни ручку біля OUT2 і відпусти на OUT4. Ця дія переносить лише вибраний провід, навіть якщо контакт має кілька з’єднань. Колір, ідентифікатор проводу та ручні згини зберігаються. Перевірка схеми та зв’язані команди оновлюються після перенесення; для збереження натисни ✓.

Esc, відпускання на порожньому місці або на початковому контакті залишають з’єднання незмінним. З’єднати обидва кінці в одному контакті чи дублювати вже наявний провід не можна. Під час перетягування контакт-призначення підсвічується зеленим або червоним. Undo/Redo повертає або повторює зміну. Позначки фізичного звіряння скидаються після зміни з’єднання.

Перетягування з контакту, навіть уже підключеного, створює новий провід. Перенесення наявного проводу починається лише з кінцевої ручки вибраного проводу. З’єднання кліками потребує явної дії «Під’єднати провід» у довідці контакту. Для перенесення з клавіатури сфокусуй круглу ручку та натисни Enter або Space, після чого обери новий контакт; також доступні кнопки «Замінити…» у властивостях проводу.
