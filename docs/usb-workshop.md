# Локальний режим розробника: Arduino CLI через USB

Для учнів використовуйте [браузерний режим без локального сервера](classroom-web-usb.md). Цей документ описує альтернативний режим розробника. Він замінює постійну базову прошивку окремим Arduino-скетчем; для повернення до оновлень без BOOT браузерній майстерні потрібно знову встановити базову прошивку.

Відкрити **http://127.0.0.1:5173/?transport=local**. Це наша локальна вебаплікація на Blockly, з кнопкою **«Прошити»**. Установлювати Arduino IDE або вводити команди для кожного запису не потрібно.

## Запуск на цьому Mac

```sh
cd /Users/vmyronovych/projects/mcar
npm run dev --prefix web
```

Залиште цей термінал відкритим. У Chrome відкрийте адресу вище. Сервер прив’язаний до `127.0.0.1`; локальний Arduino CLI та пакет ESP32 3.3.0 вже встановлені в `.cache/arduino/`. Після запуску інтернет не потрібен. Статичний HTML або `vite preview` самі по собі не компілюють і не прошивають: потрібен саме локальний dev-сервер із USB-службою.

## Як користуватися

1. Підключіть USB до самого ESP32. Для поточного тесту плата окремо, без моторів і батарей.
2. Складіть блоки під **«коли плата увімкнеться»**. Початковий приклад уже блимає світлодіодом. Змініть паузи або виберіть «Чистий аркуш».
3. Праворуч оберіть USB-плату й натисніть **«Прошити»**. Поточну програму на платі буде замінено.
4. Дочекайтеся компіляції, запису та перевірки запуску. Не від’єднуйте USB під час запису.
5. Програма запускається одразу після прошивання. Кнопка EN запускає її спочатку. Вона залишається у flash після від’єднання від комп’ютера й працює при наступному живленні.

Зміни блоків під час прошивання зберігаються у браузері, але поточний запис використовує знімок програми на момент натискання. Для нової версії натисніть «Прошити» знову. Кнопки «Зберегти» й «Відкрити» працюють із файлами `.mcar` формату `mandrivnyk-usb`, окремого від Wi-Fi-програм машинки. Вибір прикладу спочатку завантажує резервну копію поточної програми.

## Що показує панель прошивання

Під час роботи кнопка залишається контрастною, але повторний запис заблоковано. Панель показує поточний етап і час від початку операції. Для компіляції використовується індикатор активності без вигаданого відсотка; для USB-запису — відсоток із журналу esptool. Прошивка містить кілька образів, тому відсоток стосується поточного образу й починається заново для наступного. Завершення перевірки запуску має окремий зелений стан; непідтверджений запуск та помилка відображаються окремо.

USB-порт можна змінити в «Налаштуваннях підключення». Якщо знайдено кілька плат, цей розділ відкривається автоматично. Кнопка «Уся програма» в редакторі вміщує блоки у видимій області. Зображення плати є ілюстрацією, а не індикатором реального стану LED.

## Блоки

- Початок після ввімкнення / перезапуску.
- Світлодіод: увімкнути, вимкнути; GPIO2 підтверджено на цій платі.
- Чекати 0–60 секунд.
- Завжди, повторити 0–1000 разів, поки / доки, якщо / інакше.
- Числа, арифметика, порівняння, логічні операції, до 8 змінних.

Максимум 256 блоків та 8 рівнів вкладених команд. Недопустимі числа або ділення на нуль зупиняють програму й гасять LED. Після скінченної програми останній стан LED зберігається; «завжди» працює до перезапуску/вимкнення. GPIO, ШІМ, власні параметризовані команди та конструктор підключень описані в [інструкції для класу](classroom-web-usb.md).

## Що відбувається після натискання

Blockly-граф → перевірений Arduino-скетч → локальний Arduino CLI → USB flash → до 7 секунд читання Serial. Це новий самостійний образ прошивки, не передавання MCAR2-команд у прошивку машинки. «Показати Arduino-код» відкриває згенерований код. Журнал показує помилки компіляції, USB-запису та повідомлення плати.

«Програма запустилася» означає, що отримано стартовий маркер `MCAR_USB_BLOCKS BOOT`. Це не гарантія правильності всієї логіки: помилка може статися пізніше за коротке вікно спостереження. Саме світло перевіряє людина. Якщо порт зайнятий, закрийте інші Serial Monitor. Якщо запис чекає на `Connecting`, утримуйте BOOT до початку запису.

## Реалізація та перевірка

- `web/src/usb-blocks.js`, `usb-compiler.js`: блоки та генерація C++ з обмеженого набору команд.
- `web/src/usb-main.js`, `web/index.html`: редактор, збереження та інтерфейс прошивання.
- `web/server/usb-workshop.js`: локальна служба як Vite plugin, один запис за раз.
- `tools/monitor_usb_blocks.py`: читання Serial після запису.
- `.cache/usb-workshop/`: згенеровані скетчі, двійкові файли та кеш компілятора.

Служба приймає тільки локальні запити з дозволеним Host/Origin; запис вимагає токен цієї сесії. Сервер сам генерує код із перевірених блоків. Клієнт не може передати shell-команди, довільний C++, параметри компілятора чи довільний шлях пристрою. Порт має бути серед виявлених USB-портів Mac. Інші ОС цим переліком портів поки не підтримуються. USB-сторінку та її окремі ресурси не вбудовуємо у прошивку машинки.

```sh
npm test --prefix web
npm run test:e2e --prefix web -- --config playwright.usb.config.js
npm run build --prefix web
```

Ці браузерні тести використовують підставний USB API та не прошивають пристрій. Окремий `node scripts/check-usb-hardware.mjs` із папки `web` виконує справжній запис прикладу Blink на підключену плату; запускати його тільки свідомо.
