# Майстерня v0.2: протокол і межі

## Архітектура

`Blockly (браузер) → компілятор MCAR2 → HTTP на ESP32 → перевірка графа → NVS → виконавець C++ → штатна задача моторів`.

Весь редактор, українські переклади й медіафайли зібрані локально у gzip-масиви `firmware/src/workshop_assets.h`. ESP32 роздає їх із flash. Браузер не завантажує скрипти з CDN. Після встановлення не потрібні інтернет, обліковий запис або сервер компіляції. Режим точки доступу і карта GPIO не змінилися.

Генератор не використовує `eval` і не приймає довільний C++/JavaScript. Дитячі блоки не можуть перепризначити GPIO або вимкнути перевірку батареї/FAULT. Задача моторів працює кожні 20 мс незалежно від WebServer. Режим BLOCKS використовує ті самі обмеження струму, PWM, плавний реверс і фізичний STOP.

## MCAR2

Перший рядок `MCAR2`, далі одна команда на рядок, завершення `H`. LF, максимум 4096 байтів і 256 інструкцій. Аргумент відділяється комою. Стек до 32 значень float, абсолютна величина ≤1 000 000; NaN/Infinity, переповнення та ділення на нуль зупиняють програму. Змінні 0–7 учнівські, 8–15 для вкладених повторень; на старті всі нулі.

Приклад «швидкість 80, вперед 2 секунди»:

```text
MCAR2
P,80
S
P,2
P,1000
*
F
H
```

| Інструкція | Дія |
|---|---|
| `P,n` | Покласти константу на стек |
| `V,i`, `=,i` | Прочитати/записати змінну |
| `I,i` | Зняти ціле 0…50 і записати лічильник повторень |
| `+ - * / ^` | Дві вершини стека: a op b; ^ = степінь |
| `< > E N Q G` | a&lt;b, a&gt;b, дорівнює, не дорівнює, ≤, ≥ |
| `! & \|` | Заперечення та дві булеві операції. Компілятор Blockly реалізує і/або переходами з коротким обчисленням |
| `s,i`, `d,i` | Сирий ADC / нормалізована темрява сенсора 0…4 |
| `e`, `b`, `t` | Положення лінії, VBAT_SW у вольтах, стан GPIO13 кнопки |
| `S`, `K` | Зняти швидкість 0…180 / Kp 0…100 |
| `F B L R W A` | Зняти тривалість 20…10000 мс: вперед, назад, дуга ліворуч, праворуч, чекати, слідувати лінії |
| `Y` | Стек: лівий PWM, правий PWM, мс; керувати двома боками |
| `M,i` | Стек: PWM, мс; керувати лише мотором i=0 LF,1 RF,2 LR,3 RR |
| `Z` | Негайний нуль завдання моторів, програма триває наступного циклу |
| `H` | Завершити програму й зупинити |
| `J,pc`, `C,pc` | Безумовний перехід / перехід, якщо зняте значення дорівнює нулю |

Компілятор підтримує одну приєднану програму з жовтим початком, до 8 числових змінних та 8 вкладених повторень. Перед збереженням ESP32 перевіряє всі opcodes, аргументи, адреси, дефіцит/переповнення стека та однакову висоту стека при злитті гілок, включно зі зворотними переходами. Нескінченні цикли отримують максимум 64 інструкції за один цикл задачі; решта задач продовжують роботу. Загальний ліміт виконання 120 с. Це не вимога, щоб кожний можливий шлях гарантовано завершився раніше: довгі/нескінченні програми зупинить часовий ліміт.

Читання темряви/помилки та стеження за лінією потребують калібрування. Сира ADC й батарея не потребують калібрування лінії. Утримана GPIO13 забороняє новий запуск будь-якого рухового режиму. GPIO13 також є STOP: натискання під час виконання перериває програму раніше, ніж учнівська умова зможе використати кнопку для руху. Для окремої ігрової кнопки потрібні новий модуль/вхід і блок, не обхід STOP.

## API

| Метод і шлях | Контракт |
|---|---|
| GET `/api/info` | `product=mandrivnyk-4wd`, `protocol=2`, версія, id/назва робота, `otaMaxSize` |
| GET `/status` | Наявні voltage/raw/speed/kp/calibrated/mode/reason + `maintenance` |
| POST `/api/program` | `text/plain`, MCAR2 ≤4096 байтів; успіх JSON `{hash: "xxxxxxxx"}`; запис NVS має завершитися до підтвердження |
| GET `/api/program` | Збережений MCAR2; це не JSON робочого поля Blockly |
| POST `/api/run?hash=…` | Запускає лише програму з такою FNV-1a 32-бітною сумою. Це контроль відповідності, не криптографічний підпис |
| POST `/stop` | Зупиняє всі режими; завжди доступний |
| POST `/cal?surface=white\|black` | Калібрування на місці; заборонено під час OTA |
| POST `/api/ota/prepare` | Тіло: 6 цифр PIN. Достатня батарея ≥4,6 В, немає FAULT/калібрування. Зупинка моторів, maintenance, випадковий 128-бітний token |
| POST `/api/ota/unlock` | `X-OTA-Token`, фізична кнопка затиснута; дозвіл на 60 с |
| POST `/api/ota?size=N` | Той самий заголовок, один multipart файл; довжина дорівнює N; N не перевищує резервний app розділ |
| POST `/api/ota/cancel` | Той самий token; вихід зі STOP, без самостійного запуску |

Після 5 неправильних PIN — пауза 30 с. PIN створюється випадково на першому запуску, зберігається у NVS та показується тільки через Serial. Сеанс підготовки закінчується через 120 с, якщо запис не триває. На час запису мотори примусово в нулі; beginRun відмовляє, button-release не запускає лінію/програму. Напруга під записом не нижче 4,2 В, інакше запис переривається. Після збою фізичну кнопку треба відпустити; робот лишається зупиненим.

OTA пише в неактивний app розділ. Після отримання рівно N байтів, завершення єдиного multipart файла та всієї HTTP заявки `Update.end(false)` перевіряє образ; тільки тоді обирається новий boot розділ. Другий файл у запиті відхиляється. Перерваний/невалідний запис не робить частковий образ активним. **Автоматичний rollback при логічно несправній, але коректно зібраній новій прошивці не ввімкнений**; відновлення — USB. Bootloader/таблиця розділів через це OTA не змінюються.

Канал локальний HTTP у захищеній паролем AP, без TLS/підписування образів. PIN та фізична кнопка обмежують випадкові/сторонні оновлення, але це не система захищеного промислового boot. Дитячі програми можуть завантажувати підключені до AP учні; один клієнт на робот. Не відкривати цей сервер в інтернет.

## Сумісність і перевірки

Старий інтерфейс послідовностей лишився на `/control`; старі `/program`, `/run`, `/drive` з epoch та інші маршрути збережено. Сторінка `/` тепер відкриває Blockly. Після збереження MCAR2 довге натискання вибирає його; після legacy `/program` у поточному запуску вибирається legacy програма. При перезавантаженні пріоритет має валідний MCAR2, якщо він є у NVS.

Тести `web/tests/compiler.test.mjs` створюють реальний байткод із Blockly. `firmware/tests/block_vm_test.cpp` читає ті самі файли з `validation/block-fixtures` і виконує їх. Playwright перевіряє український інтерфейс, передачу, недозвіл запуску після редагування, збереження, імпорт, мобільний екран та сценарій OTA із замоканим HTTP. Справжній compile ESP32 перевіряється окремо, а OTA/RF/механіка на пристрої — за приймальним протоколом.
