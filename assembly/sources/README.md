# Джерела посібника та 3D-моделі

**10.11.2026:** повну машинку, браузерні кроки, PDF та OBJ перебудовано на уточненому корпусі. Старий овальний контур більше не використовується в монтажних сценах.

## Спільна геометрія

- `chassis-photo-trace.json` — контур пластини й 72 отвори за фотографіями. Габарит 255 × 150 мм, товщина 3 мм, проміжок 30 мм надані власником; координати отворів оцінні.
- `../../tools/triangulate_chassis.mjs` — сітка без заповнення отворів. Колінеарні ребра розділено для стикування з бічними стінками; 1409 трикутників на поверхню.
- `chassis_geometry.py` — обидві поверхні та всі бічні стінки. Нижня пластина z=0…3, верхня z=33…36 мм. Джерела й початок координат ті самі, що в `../../web/src/assembly/chassis-review-3d.js`.
- `battery-measurements.json` — виміряний габарит 58 × 62 × 18 мм по x/y/z. Відсік знизу, z=−18…0. Точні XY, орієнтація та товщина скотчу невідомі; центральне положення лише для перегляду.
- `robot_model.py` — повна машинка: корпус, мотори, колеса, опори, габарит відсіку, умовні AA, датчик і електроніка.
- `assembly_steps.py` — спільні українські кроки для PDF і браузера. Відсік та AA показуються знизу; знімати верх для AA не потрібно.

`geometry.json` зберігає три різні типи даних: `measured` (замір або null), історичний `illustrative` і `assembly_display` (схематичні позиції невиміряних компонентів). Старі розміри пластин, висота й габарит батареї з `illustrative` перекриті даними уточненого перегляду в `robot_model.py`. Інші розміри та посадки моторів/коліс, опор, кронштейна й електроніки залишаються приблизними. Напрям фото A прийнято за перед лише для візуалізації. Умовна підлога не є виміром кліренсу.

Відсік показується габаритом без вигаданих стінок, отворів, ремінців або шару скотчу. У браузері він прозорий, у PDF після появи AA — каркасний. AA всередині — умовні зображення, не точна модель внутрішнього пристрою відсіку. Повідомлений власником зазор 3–4 мм стосується примірки до приклеювання; остаточний зазор і утримання ще потребують перевірки.

## Відтворення

Для Python потрібні `reportlab`, `numpy`, `Pillow`; для перевірки PDF — `pypdf`. Шрифти Arial на macOS або DejaVu Sans на Linux (`MCAR_FONT_DIR`). З кореня:

```sh
node tools/triangulate_chassis.mjs
python3 assembly/sources/build_manual.py
python3 tools/export_assembly.py
npm test --prefix web
npm run test:e2e --prefix web
npm run build --prefix web
python3 tools/check_project.py
```

`build_manual.py` створює 31-сторінковий A4-посібник `../assembly-manual.pdf`, рендери `../renders`, `model-demo.obj` і маніфести деталей та сторінок. Ортографічний рендер використовує буфер глибини; кроки відсіку й AA мають вигляд знизу. На решті сторінок — спільний ракурс. Лінії джгутів ілюструють маршрут, контакти визначені у `../../docs/wiring.md`.

`../../tools/export_assembly.py` створює `../../web/src/assembly/model-data.json`; його не редагують вручну. `npm run build` виконує експорт автоматично. Браузер може підняти верх для огляду електроніки на умовні 82 мм; жоден монтажний крок тепер не вимагає такого підйому.

Тести звіряють відкриті отвори, замкненість сітки, габарити та зазор пластин, батарейний габарит, вершини OBJ, порядок сторінок, незмінні нижні кінці проводів під час підйому, 30 гнізд ESP32 та 90 периферійних контактів. Це програмні перевірки, не випробування фізичного робота.

`export_template.py` як і раніше відмовляється створювати виробничий шаблон без повного набору замірів. Статуси `PHOTO_TRACE_NOT_MEASURED_CAD` для корпусу та `ILLUSTRATIVE_NOT_FOR_MANUFACTURE` для повної машинки збережені. Архів v0.3 і готові release-образи містять попередню версію; ця перебудова їх не перевидає.
